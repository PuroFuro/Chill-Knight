# Deploying Chill Knight

The two halves deploy to **different** places, because they're different kinds of
service:

| Part       | Where                              | Why |
| ---------- | ---------------------------------- | --- |
| `frontend` | **Vercel** (static site)           | It's a Vite SPA — perfect for Vercel. |
| `backend`  | **Render / Railway / Fly / a VPS** | It holds long-lived WebSocket connections and runs a continuous in-memory game loop. Vercel is serverless and **cannot** do that. |

> **Why not the backend on Vercel?** Serverless functions are request→response,
> time-limited, and stateless. This server keeps a WebSocket open for the whole
> play session, runs a 20 Hz game loop in a background task, and keeps every live
> World in one process's RAM. That needs a single, always-on process — not
> serverless. So the backend goes on a host that runs a persistent container.

---

## 1. Deploy the backend first (you need its URL for the frontend)

Files added for this: `backend/Dockerfile`, `backend/.dockerignore`, `render.yaml`.

### Option A — Render (one-click via the included blueprint)

1. Push this repo to GitHub.
2. In Render: **New → Blueprint**, pick the repo. It reads `render.yaml`, builds
   `backend/Dockerfile`, and creates one web service.
3. In the service's **Environment** tab set:
   - `DATABASE_URL` — your Supabase URL, e.g.
     `postgresql+asyncpg://postgres.<REF>:<PASSWORD>@aws-0-<region>.pooler.supabase.com:6543/postgres`
     (use the **transaction pooler**, port 6543, for hosted deployments)
   - `CORS_ORIGINS` — your Vercel URL, e.g. `https://chill-knight.vercel.app`
     (you'll get this in step 2; you can fill it in after and redeploy)
   - `SECRET_KEY` is auto-generated by the blueprint.
4. Note the public URL, e.g. `https://chill-knight-backend.onrender.com`.

### Option B — Railway / Fly / any container host

Point it at `backend/Dockerfile` and set the same three env vars
(`DATABASE_URL`, `SECRET_KEY`, `CORS_ORIGINS`). The container reads `$PORT`
automatically. Generate `SECRET_KEY` with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

> ⚠️ **Run exactly one instance.** Do not enable horizontal scaling / multiple
> replicas and do not raise Uvicorn `--workers`. All world state lives in one
> process's memory, so a second instance is a separate, invisible set of worlds.
> (Account progress is always safe — it's flushed to Supabase continuously.)

## 2. Deploy the frontend to Vercel

File added for this: `frontend/vercel.json`.

1. In Vercel: **New Project → import this repo**.
2. Set **Root Directory = `frontend`**. Vercel auto-detects Vite (build
   `npm run build`, output `dist`).
3. Add an Environment Variable:
   - `VITE_API_URL` = your backend URL from step 1
     (e.g. `https://chill-knight-backend.onrender.com`, no trailing slash)
   - The app turns this into the `wss://…/ws` WebSocket URL automatically.
   - It's baked in at **build time**, so redeploy if you change it.
4. Deploy. Then go back and make sure the backend's `CORS_ORIGINS` includes this
   Vercel domain.

## Checklist

- [ ] Backend: `DATABASE_URL` → Supabase (pooler, port 6543)
- [ ] Backend: `SECRET_KEY` → long random value (not the default)
- [ ] Backend: `CORS_ORIGINS` → exact Vercel URL(s), no trailing slash
- [ ] Backend: single instance only
- [ ] Frontend: `VITE_API_URL` → backend URL, then redeploy
- [ ] Open `https://<backend>/api/health` → `{"status":"ok",...}`
